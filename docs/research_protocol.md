# SmolVLA微调研究协议（2026-11-19）

## 第一阶段目标与不做的事情

优先研究**数据高效视觉适配**：以`lerobot/smolvla_libero`为冻结基线，针对可证明来自新相机条件的少量成功示范进行LoRA微调，并且评估原域保持与新域能力。当前不启动GPU、不自动下载数据、不训练Recovery与WAM，不碰`/root/autodl-tmp/corrector`。

### 实验矩阵

| ID | 初始权重 | 新训练数据 | 结论范围 |
|---|---|---|---|
| B0 | `smolvla_libero` | 无 | 已有策略在匹配条件下的起点 |
| L1 | B0 | 已审计的新视角示范 | Expert LoRA能否改善该观察分布 |
| L2 | B0 | 与L1严格相同 | Vision/Connector方向LoRA，对照**待实现，不能用当前CLI冒充** |
| L3 | B0 | 已审计的新视角示范＋有来源的原始数据 | 保持原能力的权衡，后续 |
| R1（后续） | B0 | Recovery L1/L2专家恢复示范 | 从失败状态继续完成任务，不和视角适配混为一组 |

另将`smolvla_base`开始适配原始LIBERO作为**训练技术学习支线**。它和B0的初始权重不同，不能合并为视角微调效果对照。

### 冻结评测的优先顺序

1. 审计同一物理初始条件、语言指令、动作执行窗口、推理参数、初始噪声和运行资产版本。
2. 先保持不微调的B0在原始LIBERO与已知LIBERO-plus条件下执行，固定H20作为主协议，同时保留H50检查，源于已有32条件`H20=20/32`、`H50=7/32`的有限证据，非“最优窗口”定理。
3. 使用同一训练来源和固定预算、固定可训练模块定义进行LoRA；每个Run都保存初始化和目标模块名单、参数数量、训练step、GPU时间、train/val loss、Checkpoint完整性和完整训练续接状态。
4. 只在真实模型+真实Batch中核对Input形状和Loss/Padding；之前历史训练batch见`[B,1,3,256,256]`视觉、`[B,1,8]`状态、`[B,50,7]`动作，实际来源应以本次为准。
5. 固定验证集选模型，保留测试视角/来源进行最后评估；按配对condition/seed报告成功率、失败转移、计算开销、原域遗忘。不能把离线MSE或少数视频称为稳健泛化。
6. 第一版只比较B0和L1；L2/R1在明确来源且首轮成功后单独实施。

### 工程安全

2号机`df`回传：数据盘当前总550GB、已用415GB、余136GB；RTX4090 24GB显存其中约9.6GB由Corrector训练占用，77%GPU Util。正式允许新GPU训练前：Corrector完成或停止并确认其状态归档、实际Compute PIDs为空、模型/数据/源码版本冻结、可重复读取真实Batch、仍留≥30GiB空余。**不建议在S2_s42训练期间抢卡；剩余显存并非空闲授权。**

第一版工具`plan-train`只打印经过配置检查的官方`lerobot-train`CLI，模板未填SHA和Episode时会拒绝，`launch-train`必须人工提供确认且确认显卡无其他Compute进程。即使通过门槛也不等于已经完成闭环评测。
